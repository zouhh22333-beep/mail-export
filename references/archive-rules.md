# 本地归档约定

## 运行条件与边界

`scripts/archive_store.py` 使用 Python 3.10 或更新版本的标准库，无第三方依赖。它只处理当前机器可访问的文件和文本，不连接邮箱，不接收认证信息，也不会替 agent 调用连接器。

通过宿主工具取得邮件或附件后，把本地路径交给脚本。默认文件名来自 `original_name`；只有用户要求改名时填写 `save_name`。没有原始邮件文件名时，用主题和真实格式扩展名；没有主题时用“无主题”。对于没有文件名的附件，先从元数据补齐；确实没有时用 `fallback_name` 提供可区分的备用名称，保留原名字段为空，并在结果中说明。脚本未取得备用名称时使用“附件_部分标识”，不猜测扩展名。

## 归档结构

```text
用户指定目录/
├── .mail-export/
│   ├── archive.sqlite       索引与文件校验信息
│   └── archive.lock         仅运行期间存在
└── 邮件主题/
    ├── 原始邮件名.eml       仅在取得真实原始邮件时
    └── attachments/
        ├── 原始附件名.pdf
        └── 原始附件名 (2).pdf
```

不同账号或不同邮件拥有各自的默认邮件目录；同主题时追加序号。原始文件名中不兼容文件系统的字符会被替换，保留名称会调整，超长名称会缩短并尽量保留扩展名。脚本为序号保留少量名称长度空间。用户要求的分类目录通过 `directory` 指定，与默认邮件目录二选一。

索引以 `account_id + message_id + part_id` 为文件身份，记录原名、请求名称、实际相对路径、字节数、SHA-256、状态、时间和错误。具体标识来源见 [连接器使用约定](connector-tools.md)。去重按身份执行，同名附件仍是不同文件。

## 输入清单

每批写一个 UTF-8 JSON 文件。清单可以保存在宿主临时工作目录；含正文的清单属于邮件数据，避免写入共享代码仓库或日志。示例中的 ID 和路径仅表示格式，执行时替换为真实工具结果。

```json
{
  "version": 1,
  "account_id": "connector:account-1",
  "items": [
    {
      "message_id": "message-123",
      "subject": "十月账单",
      "part_id": "attachment:att-456",
      "kind": "attachment",
      "original_name": "账单.pdf",
      "source_path": "C:/mail-staging/download-456.pdf"
    }
  ]
}
```

| 字段 | 规则 |
| --- | --- |
| `version` | 固定为数字 `1` |
| `account_id` | 账号的稳定身份；一批只处理一个账号 |
| `items` | 每项代表一个文件，不能把一封邮件的多个附件合并成一项 |
| `message_id` | 必填，稳定邮件身份 |
| `subject` | 邮件主题字符串；没有时省略或使用空字符串 |
| `part_id` | 必填，同一邮件中的稳定文件身份；例如 `raw`、`body-text`、`attachment:真实附件ID` |
| `kind` | `email` 或 `attachment` |
| `original_name` | 原始文件名，不包含保存目录；确实缺失时省略、为空或 null |
| `save_name` | 仅用户要求改名时提供；名称应包含与内容一致的扩展名 |
| `fallback_name` | 原名缺失时使用的备用名；不覆盖有效原名或用户指定名称，扩展名仅按已知真实类型确定 |
| `directory` | 用户指定的相对目录组件数组，例如 `["2026-10", "发票"]`；省略时采用默认邮件目录 |
| `source_path` | 已下载文件的绝对路径，按字节复制，不重编码 |
| `text` | 需要保存的完整文本，使用 UTF-8 写入；与 `source_path` 二选一 |
| `error` | 标记获取失败，不提供文件来源；脚本记录通用 `connector_error`，避免泄露工具错误中的令牌或正文 |

`directory` 是**完整的相对目标目录**，指定后不会再自动追加主题或 `attachments`。空数组表示直接保存到目标根目录。组件不能包含路径分隔符、绝对路径、`.` 或 `..`；`.mail-export` 为索引保留目录。即使命名模板产生目录文字，也先分离成合法组件再传入。

原始邮件无名称且 `source_path` 的真实格式为 EML 时，脚本可根据主题生成 `.eml` 名称；直接传入 `text` 时默认生成 `.txt`。其他格式应明确给出真实文件名。例如完整 HTML 正文可提供 `original_name: "主题.html"` 与 `text`，但不应把文本写成 PDF、Word 或其他二进制格式。

## 调用顺序

以下为命令结构。`<skill目录>`、`<归档目录>` 和 `<清单路径>` 必须由当前 agent 解析为真实路径，并作为独立参数正确引用；不要将任何邮件字段插入命令字符串。

```text
python "<skill目录>/scripts/archive_store.py" check --root "<归档目录>" --manifest "<清单路径>"
python "<skill目录>/scripts/archive_store.py" import --root "<归档目录>" --manifest "<清单路径>"
python "<skill目录>/scripts/archive_store.py" status --root "<归档目录>"
```

1. 列表阶段构建只含身份、主题、名称等元数据的清单，执行 `check`。此阶段可以省略 `source_path`、`text` 和 `error`。
2. `skipped` 代表已验证存在且内容与索引一致，无需重新下载；`pending` 代表需要获取。`failed` 需先解决清单或路径问题。
3. 只为待处理项调用连接器。构建待导入清单，逐项补充 `source_path` 或 `text`；下载失败的项改为填写 `error`。
4. 执行 `import`，读取 JSON 结果与退出码，保存失败明细。下一批沿用同一归档根目录。
5. 重试时先重新执行 `check`；只重新获取待处理项。不要依赖上次进程的内存状态。

`check` 会创建归档目录、索引和短暂的锁，也可修复“文件已完成但索引尚未提交”的状态，因此它不是完全无写入的预览命令。它不下载邮件、不创建用户文件。

`status` 汇报索引中的全部文件并验证文件内容，适合检查或恢复时使用；日常逐批执行优先用 `check`，避免反复扫描整个历史归档。`check` 和 `import` 针对当前清单计数，`status` 针对索引中已有记录计数，均不能据此推断邮箱匹配总数。

## 输出与退出码

正常执行在标准输出返回一份 JSON：

```json
{
  "version": 1,
  "command": "import",
  "root": "C:/MailArchive",
  "unit": "artifacts",
  "counts": {"saved": 1, "skipped": 0, "pending": 0, "failed": 0},
  "results": [
    {
      "message_id": "message-123",
      "part_id": "attachment:att-456",
      "original_name": "账单.pdf",
      "requested_name": null,
      "state": "saved",
      "path": "C:/MailArchive/十月账单/attachments/账单.pdf"
    }
  ]
}
```

实际结果还可能带有大小、SHA-256、错误或警告。所有计数单位都是文件，agent 应结合本次所需文件清单单独计算邮件完成数。

- `0`：命令执行正常；`check` 中的 `pending` 仍需下载，`status` 中的失败项仍需处理。
- `1`：`check` 或 `import` 至少一项失败，检查逐项结果；其他成功项仍有效。
- `2`：整体清单、索引、锁或环境错误，停止当前调用并检查原因。命令行语法错误由参数解析器输出到标准错误。

## 完整性、重名与中断

文件先写入目标目录内的临时文件，校验完成后再发布到最终名称并记录成功。若已有同名文件，保留已有文件并追加序号。Windows 使用不覆盖目标的同目录重命名；其他系统优先使用不覆盖目标的发布方式，不支持时采用独占创建后复制，只有写入并校验完成才成功。

脚本对已归档文件校验大小与 SHA-256。文件被删除或修改时视为待处理，重新导入时保留现有修改文件并生成新副本。相同身份但新名称或新目录要求不会自动移动已保存文件，返回 `skipped` 及相关警告；需要单独执行用户授权的重排，不能宣称新命名已经生效。

索引和归档目录应由当前任务管理；脚本检查路径仍位于目标根目录内，并拒绝通过符号链接等逃逸。不要同时在同一根目录运行多个归档进程。正常退出会释放 `.mail-export/archive.lock`；异常终止可能留下锁，只有核实没有运行中的任务后，才能删除这个确切的锁文件再继续，不能自动猜测锁已过期。

异常终止可能遗留临时文件或未记为成功的半成品。续跑先检查索引和内容；不匹配的已有文件不会被覆盖。清理时只处理经确认属于该任务的临时文件，不递归清空目标目录。

本地索引记录的是已交给脚本的项。查询条件、分页完成情况、尚未取得的邮件以及用户命名模板的序号映射由 agent 按批记录在任务工作目录中；仅有本地成功索引不能证明邮箱范围已全部导出。
