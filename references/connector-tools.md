# 连接器使用约定

本 skill 安装在 Domi 等已有邮箱连接的 agent 内。实际工具名和参数以该环境公开的工具描述为准；本文件描述需要查明的能力，不提供虚构的 API 名称。

## 首次映射

| 能力 | 从真实工具说明或返回值确认 |
| --- | --- |
| 账号与文件夹 | 当前已授权账号、可访问文件夹；已有明确账号时不必额外枚举全部账号 |
| 查询与分页 | 支持哪些筛选、时间字段、排序、页大小、游标及终止条件 |
| 邮件身份 | 邮件标识是否跨页稳定，是否仅在某账号或文件夹中唯一 |
| 完整正文 | 全文或截断内容、纯文本或 HTML、是否需要单独获取 |
| 原始邮件 | 是否可导出真实原始字节和文件名；不存在时不能声称支持 EML |
| 附件列表 | 附件标识、原始名称、大小、是否有嵌入图片及其区分字段 |
| 附件内容 | 是否返回已下载文件、受控下载资源或内容字节；遵循实际下载工具契约 |
| 本地文件操作 | 下载结果所在的机器、可访问目录、能否运行 Python、读写及验证文件 |
| 读信副作用 | 是否有只读或保持未读选项；不得凭空填写不支持的参数 |

只核查当前任务需要的能力。例如仅导出附件时，无须先获取每封邮件正文。

## 标识映射

- `account_id`：邮箱工具提供的稳定账号 ID；多个连接器时加入稳定的连接来源区分，避免碰撞。不要使用访问令牌作为标识。
- `message_id`：工具提供的稳定邮件 ID。若仅在文件夹内唯一，加入文件夹 ID；采用 IMAP UID 时，还需要加入 UIDVALIDITY。避免依赖可能重复、缺失的主题或 Message-ID 邮件头。
- `part_id`：原始邮件可用 `raw`，纯文本正文可用 `body-text`，附件使用 `attachment:` 加真实稳定附件 ID。原始邮件与正文分别记为不同文件。
- 工具没有稳定附件 ID 时，使用它提供的稳定部分序号或 MIME 部分位置。不能只按名称去重。若只能确定内容一致性，可用下载后内容摘要与可区分的部分位置建立本地身份；说明这种情况无法在下载前可靠跳过附件。
- 无法确定稳定身份时不要伪造跨运行去重保证。可先完成本次导出，明确后续需重新核对。

## 查询与下载

尽可能把筛选下推到连接器。连接器不支持的条件只在必要字段上本地补筛。主题、发件人和日期筛选通常不需要模型逐封解释正文。

每页处理后记录已发现的邮件和文件身份。游标失效时可以重新查询并依靠稳定身份去重，不通过猜测游标继续执行。未取得完整分页结果时，匹配数量只能标成“目前发现”。

附件数据通过真实下载工具或宿主支持的文件传递机制保存到暂存目录。不要将二进制附件转成聊天文本再凭模型重建。下载链接可能包含令牌，不写入归档索引或用户可见日志；链接失效时重新从连接器获取。

如果工具提供下载校验信息（大小、摘要等），保存前按其契约校验。仅“调用返回成功”但没有可读取文件，不足以确认本地归档完成。

没有公开可直接调用的连接器 API 时，Python 辅助脚本不应尝试调用 agent 内的工具名；由 agent 先调用工具取得文件，再将路径交给脚本。
