# Mail Export Skill

按条件批量保存邮件与原始附件到本地文件夹。QQ 邮箱可通过自带的只读 IMAP 脚本直接下载真实文件；实际支持文件下载的连接器也可以复用。

## Domi / QQ 邮箱下载

Domi 的 `mailbox_read_attachment` 只能提取附件文字。`scripts/qq_imap_export.py` 直接从 QQ 邮箱读取原始邮件、解码真实附件，并交给归档脚本保存，无需网页登录。

使用前在 **Domi 实际运行脚本的环境** 本地配置 `QQ_EMAIL_ACCOUNT` 和 `QQ_EMAIL_AUTH_CODE`（邮箱客户端授权码）。仅在连接器中配置过，不代表脚本能访问这些凭据。完整步骤和任务参数见 [QQ IMAP 下载说明](references/qq-imap.md)。

## 功能

- 按账号、文件夹、时间、发件人或主题等条件选择邮件，实际可用条件取决于连接器。
- 用户指定命名规则优先；未指定时保留原名，缺少原名时使用稳定的备用名称。
- 同名文件追加序号，避免覆盖；记录来源和最终保存路径。
- 基于稳定邮件及附件标识去重，并通过文件大小与 SHA-256 核验本地文件。
- 支持中断续跑、部分失败记录和重试。
- 优先使用批量工具，只读取筛选、保存或命名所需内容。

## 通用性能优化

- 默认 2 个独立只读连接并发下载；连接受限时减少并发，保存顺序固定。
- 邮件头增量缓存：每次查询当前匹配 UID，只补取缺失的元数据，不影响筛选或最新排序。
- 附件字节直接归档，写入同时计算 SHA-256；保留 fsync、冲突保护和中断恢复。
- 完整缓存命中时每个文件只校验一次，跳过正文传输和成功记录的重复更新。
- 任务一次提交脚本，附带阶段耗时和传输统计，适用于不同文件夹、日期、格式与命名要求。

简历语义识别仍由宿主根据文件名、正文和必要附件内容完成，不能把 PDF 或名称关键词当作完整识别。当前仍获取完整邮件后解码附件，尚未实现按 MIME 部分下载。

离线模拟每条网络命令 80ms、10 封邮件/30 个文件：旧版首次 1.5782s、新版 1.1357s；重复运行 0.2922s → 0.1389s。导出的文件名、附件哈希相同，EML 均与源字节一致。这是机制验证，不代表 QQ 或 Domi 的真实速度承诺。

## 执行流程优化

普通导出直接配置最终目录和名称，一次运行完成，省去下载后临时编写平铺改名脚本。整月查询支持 month=YYYY-MM，自动使用次月1日作为不含的终点。

新增 [简历批量流程](references/resume-workflow.md)：prepare 批量下载候选 → Domi 实际阅读并填写分类清单 → finish 一次归档。默认 auto 布局：只有简历的邮件直接保存简历到根目录；简历加其他随附文件才建立子文件夹，同信全部材料放在里面。文件夹和独立简历同层。文件夹命名 folder_template 与文件命名 query.name_template 分开设置，无要求时使用邮件主题和原始文件名。同名目录分配序号并记录映射；未确认的候选保留待处理，不能冒充完整识别。

新流程的最终路径和去重索引同时生成；分类清单绑定候选内容哈希。旧流程自行移动文件后失效的索引不会自动修复。本次没有操作用户既有归档。

此版本已做离线一致性测试，尚未在 Domi 实测整体耗时；此前模拟下载耗时不能作为新识别流程的速度保证。

## 使用

下载仓库中的 [mail-export.zip](mail-export.zip)，解压后得到 `mail-export/` skill 目录。将该目录按宿主 agent 支持的方式添加为 skill；具体导入入口以宿主产品为准。

宿主需要 Python 3.10+、目标本地文件夹的写入能力，以及 QQ IMAP 网络访问与本地凭据（或真正支持文件下载的其他邮箱工具）。两个 Python 脚本都只使用标准库，无需额外安装 Python 包。

示例指令：

> 把最近 30 天收到的发票附件下载到我指定的本地文件夹，保留原始文件名，跳过已经完整下载的文件。

> 下载指定发件人本月的附件，按照“日期_供应商_序号”统一命名。

## 验证与限制

已完成本地命名、字节保存、重名保护、去重、续跑、部分失败及打包后命令行流程验证。归档模块 16 项、QQ IMAP 模块 10 项、性能与一致性回归 9 项、简历归档流程 12 项，共 47 项离线测试通过。覆盖单独简历与附件目录同层、多个简历不建目录、文件夹命名与重名隔离、并发结果一致、缓存补取、邮件删除、UIDVALIDITY、连接回退、文件损坏恢复、路径穿越及符号链接保护。

仓库测试命令：`python -B -m unittest discover -s tests -v`。测试使用合成邮件，不读取邮箱或凭据。测试文件不装入 skill ZIP。

2026-10-30 已使用本机环境变量中的凭据，只读连接真实 QQ 邮箱，下载一封邮件的 3 个 PDF；3 个文件均有 PDF 文件头，再次运行全部验证后跳过。还验证了另一封邮件的完整 EML 获取。邮件数据仅保存在本地测试工作目录，没有纳入本仓库或分发包。

这验证了 QQ IMAP 下载路径；Domi 内执行仍需要其运行环境具备 Python、网络权限和相同的本地凭据配置，不能自动继承连接器内部的授权信息。

仅提供文字摘要的连接器仍不能下载原始附件，QQ 路径通过直接 IMAP 补齐；超大附件的外部网盘链接、无法解码的嵌套邮件附件不在当前支持范围。远端运行目录也不等于用户电脑上的本地目录。

命名、接口及恢复流程的完整说明见 skill 内的文档。
